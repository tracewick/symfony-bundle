# Contributing to Tracewick Symfony Bundle

Thank you for your interest! This guide explains how to propose changes.

## Before you start

- For anything larger than a small fix, open an issue first so we can agree on the approach.
- This package is a Symfony bridge only. It must use Tracewick **Runtime** and **Sink** APIs.
  Do not re-implement sampling, encoding, or HTTP delivery here. Framework code does not belong
  in [`tracewick/tracewick`](https://github.com/tracewick/tracewick) (see core ADR 3).

## Development setup

You need PHP 8.2+ and Composer. `ext-excimer` is optional for unit tests; without it Tracewick
runs as a no-op.

```bash
composer install
make help   # list available targets
make ci     # run every check CI runs on a pull request
```

| Target            | What it does                                           |
|-------------------|--------------------------------------------------------|
| `make lint`       | `composer validate`, normalize, PHP-CS-Fixer           |
| `make cs-fix`     | Fix coding style and normalize `composer.json`         |
| `make stan`       | PHPStan at level `max`                                 |
| `make rector`     | Check for pending Rector refactorings                  |
| `make deps`       | Detect unused and undeclared Composer dependencies     |
| `make test`       | Run the unit test suite                                |
| `make coverage`   | Run the tests with coverage reports in `build/coverage/` |

Coverage needs [pcov](https://github.com/krakjoe/pcov) or Xdebug.

## Compatibility

| Component | Versions |
|-----------|----------|
| PHP | 8.2–8.5 |
| Symfony | 6.4, 7.x, 8.x (CI matrix: 6.4 / 7.4 / 8.1) |
| Tracewick | `^0.2` |

Symfony 6.4 on PHP 8.1 is **not** supported: this package requires PHP ≥ 8.2 like the core.

## Branching and commits

- Git flow: branch `feature/*` from `develop` and open pull requests into `develop`.
- Never push to `main` or `develop` directly.
- Conventional Commits. Repository text is English only.
- Do not add AI co-authorship trailers or “Generated by …” lines to commits or PRs.
- Before every commit, run locally what CI would catch: at least `composer cs:check`,
  `composer rector:check`, `composer stan`, and `make test-unit`. Prefer `make ci`.

## Product rules

- Fail-open: the bundle must not throw into Symfony.
- Default sink is `SpoolSink`; do not default to `PyroscopeSink` on FPM.
- Default `sampleRate` is `0.1`.
- Prefer Symfony route **names** as labels; never put raw URI / query / user ids on series labels.
- Build `UnitOfWorkProfiler` once per worker process, not once per request.
